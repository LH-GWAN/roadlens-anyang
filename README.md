# RoadLens Anyang

안양시 도로 점검 우선순위 지원 시제품
**2026년 안양시 공공데이터와 AI 활용 대학생 경진대회** 출품용

---

## 1. 프로젝트 목적

안양시 도로부속물 파손 **이력** 데이터를 지도에 표시하고, 현장에서 촬영한 도로 사진에서
포트홀과 균열을 탐지한다. 다음 다섯 항목을 결합해 **점검 우선순위**를 계산하고,
선택한 점검 대상의 순찰 순서를 만들고 처리상태를 기록한다.

```
점검 우선순위 = 0.30 × 과거 파손 이력 밀도
              + 0.25 × 사진상 파손 정도
              + 0.20 × 어린이보호구역 인접도
              + 0.15 × 도로구간 중요도
              + 0.10 × 강수 영향
```

모든 항목은 0~100 으로 정규화한다. **데이터가 없는 항목은 0점 처리하지 않고 계산에서 제외한 뒤,
남은 항목의 가중치 합이 1이 되도록 재정규화**하며 화면에 제외 사유를 표시한다.

### 이 서비스가 하지 않는 것
- 지도에 표시되는 것은 **과거 파손 이력**이며 현재 도로 상태가 아니다.
- **AI 는 보수 여부를 확정하지 않는다.** 화면과 DB 는 `AI 분석 결과` 와 `담당자 확인 결과` 를
  서로 다른 필드로 분리해 저장한다.
- 모델 파일이 없으면 탐지 결과를 만들어 표시하지 않고 "모델 파일이 필요합니다" 라고 안내한다.

### 데이터별 이용조건 확인사항
- **1, 2번(공공데이터포털)**: 각 데이터셋 상세 페이지의 **이용허락범위**를 내려받기 전에 확인한다.
  이 저장소는 원본 CSV 를 포함하지 않으며(`.gitignore` 처리), 사용자가 직접 내려받아 배치한다.
- **3번(기상청 API)**: 활용신청 후 발급받은 인증키를 사용한다. 인증키는 `.env` 에만 두고
  커밋하지 않는다. 일일 트래픽 한도가 있다.
- **4번(RDD2022)**: 국가별 하위 집합의 라이선스가 다를 수 있다.
  **미국(United_States) 하위 집합은 Google Street View 이용조건 문제가 있을 수 있어
  학습 노트북에서 기본 제외**한다(`EXCLUDE_COUNTRIES`). 다른 국가 자료도 논문·배포처의
  라이선스 표기를 직접 확인한 뒤 사용한다.
- **지도 타일**: OpenStreetMap 타일을 사용한다(ODbL). 배포 시 저작자 표시 요건을 확인한다.

### 데이터 기준일
데이터 기준일은 **CSV 의 `데이터기준일자` 열에서 읽어 화면(`1. 서비스 소개`)에 표시**한다.
이 문서에 특정 날짜를 적어 두지 않는 이유는, 사용자가 내려받은 파일의 배포 시점에 따라
값이 달라지기 때문이다. 제출 시에는 실제 사용한 파일의 기준일을 확인해 발표자료에 기재한다.

## 3. 설치

Python 3.11 또는 3.12 가 필요하다(개발·검증 환경: **Python 3.12.10 / macOS**).

```bash
cd roadlens-anyang
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

`.pt`(PyTorch) 가중치를 직접 쓰려면 `pip install ultralytics` 를 추가로 실행한다.
**`best.onnx` 만 사용한다면 ultralytics 없이 동작한다.**

> `opencv-python-headless` 는 4.x 로 고정되어 있다. 5.x 는 얼굴 탐지에 쓰는
> haarcascade XML 을 더 이상 동봉하지 않는다.

## 4. 환경변수 설정

```bash
cp .env.example .env
```

`.env` 를 열어 필요한 값을 채운다. **`.env` 는 절대 커밋하지 않는다**(`.gitignore` 에 포함).

| 변수 | 기본값 | 설명 |
|---|---|---|
| `KMA_SERVICE_KEY` | (빈 값) | 기상청 단기예보 인증키. 없으면 강수 정보를 화면에서 직접 입력 |

| `ROUTING_API_ENABLED` | false | 외부 도로망 API 연동 시에만 true |

실제 CSV 를 배치하면 초록색 "실제 내려받은 공공데이터 파일" 표시로 바뀐다.

## 6. Google Colab 학습 순서

노트북: `notebooks/안양시 공공데이터.ipynb`

1. https://figshare.com/articles/dataset/21431547 에서 **RDD2022 ZIP 을 내려받는다.**
2. 내려받은 ZIP 을 **본인 Google Drive** 에 올린다. (예: `MyDrive/RDD2022.zip`)
3. Colab 에서 노트북을 연다. `파일 > 노트북 업로드` 또는 GitHub 연동.
4. **런타임 > 런타임 유형 변경 > 하드웨어 가속기: GPU (T4)** 로 설정한다.
5. 셀을 **위에서 아래 순서대로** 실행한다.
   - `1. Google Drive 마운트` 에서 **브라우저 팝업으로 본인이 직접 인증**한다.
     이 저장소와 노트북은 계정 정보·토큰을 저장하지 않는다.
   - `2. 실행 설정` 에서 `RDD2022_ZIP_PATHS` 를 본인 경로로 수정한다.
6. **`RUN_MODE` 는 기본값이 `smoke_test`** 이다. 먼저 이대로 끝까지 실행해
   파이프라인(압축 해제 → 변환 → 학습 → 검증 → ONNX)이 도는지 확인한다.
7. 확인이 끝나면 `RUN_MODE = "prototype_train"` 으로 바꿔 다시 실행한다.
   전체 학습이 필요하면 `"full_train"` 으로 바꾼다.

| 모드 | 클래스별 이미지 상한 | epochs | imgsz | 모델 | T4 기준 소요 |
|---|---|---|---|---|---|
| `smoke_test` | 40 | 3 | 320 | yolov8n | 수 분 |
| `prototype_train` | 1,500 | 30 | 640 | yolov8n | 30분~1시간 |
| `accuracy_train` (기본) | 제한 없음 | 60 | 640 | yolov8n | 약 3시간 |
| `full_train` | 제한 없음 | 150 | 640 | yolov8s | 여러 세션 |

### 학습 중단 후 재개 · Colab 사용 한도 대비

Colab 런타임이 종료되면 `/content` 안의 파일은 **전부 사라진다.** 그래서 노트북은
체크포인트를 매 epoch 저장하고, **기본 5 epoch 마다 런타임 밖으로 복제**한다(11-A 셀).

| 미러링 방식 | 조건 | 결과 |
|---|---|---|
| `drive` (기본, Drive 마운트 시) | 1번 셀에서 Drive 마운트 | `MyDrive/roadlens_anyang/checkpoints/` 에 zip 누적 |
| `download` (Drive 미마운트 시 기본) | Chrome 의 다중 다운로드 허용 | 로컬 PC 다운로드 폴더에 zip |
| `none` | — | 런타임 종료 시 진행분 전부 소실 |

**같은 계정에서 이어서 하기**
1. 노트북을 다시 열고 0~10번 셀을 실행한다(데이터셋 재생성, 약 3분).
2. 체크포인트가 사라졌다면 11-D 셀로 번들 zip 을 복원한다.
3. 11-B 학습 셀에서 `RESUME = True` 로 바꿔 실행한다.

**사용 한도 소진 → 다른 계정으로 옮기기**
1. (기존 계정) **11-C 셀**을 실행해 체크포인트 번들 zip 을 내려받는다.
   자동 미러링을 켜 두었다면 이미 Drive 또는 다운로드 폴더에 최신 zip 이 있다.
2. (새 계정) 이 노트북을 업로드하고 **0~10번 셀을 그대로 실행**한다.
   `RANDOM_SEED`, `PARTIAL_COUNTRIES`, `PARTIAL_MAX_IMAGES_PER_COUNTRY` 를 바꾸지 않으면
   같은 데이터셋이 다시 만들어진다.
3. (새 계정) **11-D 셀**에서 번들 zip 을 올린다. 저장 당시와 설정이 다르면 경고가 출력된다.
4. (새 계정) 11-B 학습 셀에서 `RESUME = True` 로 바꿔 실행한다.

체크포인트가 쓰이는 경로(`/content/roadlens/runs`)는 Drive 마운트 여부와 관계없이 고정이다.
계정이 달라도 같은 경로로 복원되어야 이어서 학습할 수 있기 때문이다.

번들 zip 에 들어가는 것: `last.pt`, `best.pt`, `args.yaml`, `results.csv`,
그리고 저장 당시 설정을 담은 `roadlens_resume_meta.json`.

### 데이터 분할
학습·검증·시험은 **촬영 출처(국가) 기준으로 분리**한다. 사용 가능한 출처가 3개 미만이면
이미지 단위 무작위 분할로 내려가며, **그 경우 성능이 실제 일반화 성능보다 높게 측정될 수 있다는
경고가 출력된다.** 어떤 방식이 쓰였는지는 결과 JSON 의 `split_strategy` 에 기록된다.

Colab 의 마지막 셀에서 내려받은 `best.onnx` 를 아래 위치에 둔다.

roadlens-anyang/
  models/
    best.onnx     ← 여기 (권장)
    best.pt       ← 또는 여기 (ultralytics 설치 필요)

```bash
cp ~/Downloads/best.onnx roadlens-anyang/models/best.onnx
```

앱을 다시 실행하면 사이드바의 "모델" 표시가 **사용 가능** 으로 바뀐다.
모델이 없으면 `3. 사진 분석` 화면은 비식별 처리 결과만 보여주고
**탐지 결과를 만들어내지 않는다.**

## 8. 시연 순서

1. **`1. 서비스 소개`** — 서비스 목적, 데이터 기준일, 각 기능의 활성/비활성 상태와 그 사유,
   "AI 는 보수 여부를 확정하지 않는다" 안내를 보여준다.
2. **`2. 과거 파손 이력 지도`** — 위험물 유형/날짜/도로명으로 필터하고,
   마커 클러스터 → 히트맵 → 밀집구간(군집) 레이어를 차례로 전환한다.
   정제 결과(제외 사유별 건수, 중복 제거 전후 건수)를 펼쳐 보여준다.
3. **`3. 사진 분석`** — 도로 사진을 업로드한다.
   비식별 처리(얼굴 모자이크) 결과 → AI 탐지 결과 순으로 표시된다.
   유형·신뢰도·탐지 개수·파손영역 비율을 확인하고 "점검 건으로 접수" 를 누른다.
4. **`4. 점검 우선순위`** — 밀집구간 상위 지점의 총점과 **항목별 점수 / 사용된 데이터 /
   제외된 데이터 / 계산식**을 보여준다. 강수 정보가 없을 때 재정규화가 일어나는 것을 설명한다.
5. **`5. 점검목록 및 순찰경로`** — 점검 대상을 여러 개 선택하면 방문 순서, 총거리,
   지점별 점검점수, 지도 연결선이 나온다. **근사 경로 안내 문구**를 함께 보여준다.
6. **`6. 처리결과 기록`** — AI 분석 결과와 담당자 확인 결과가 **다른 필드**에 저장되는 것을
   보여주고, 상태를 `접수 → 점검예정 → 현장확인 → 보수필요 → 처리완료` 로 바꾸며
   변경 이력이 쌓이는 것을 확인한다.

## 9. 개인정보 처리 방식

- **얼굴**: OpenCV Haar cascade(정면·측면)로 탐지해 모자이크 처리한다.
  탐지기 특성상 **모든 얼굴이 탐지된다고 보장하지 않으며**, 화면에 그 사실을 표시한다.
- **번호판**: **한국 번호판 전용 탐지모델이 없으므로 기본값에서는 번호판 처리를 수행하지 않고,
  "번호판 비식별 처리는 수행하지 않았습니다" 라고 사실대로 표시한다.**
  실험 옵션으로 러시아 번호판용 보조 cascade 를 켤 수 있으나, 이 경우에도
  "제거 완료"가 아니라 "실험적 처리(정확도 미검증)" 으로 표시한다.
- **원본 사진 저장**: `.env` 의 `STORE_ORIGINAL_IMAGE` 로 제어하며 **기본값은 `false`**,
  즉 비식별 처리된 사진만 `data/processed/images/` 에 저장한다.
- **수집하지 않는 정보**: 사용자 계정, 주민등록번호, 이름, 연락처를 수집하지 않는다.
  담당자 입력란에도 "개인 식별 정보는 입력하지 마세요" 라고 안내한다.
- **보유기간**: 사진과 위치정보는 시연·심사 목적에 한해 보관하고 종료 후 삭제한다.
  안내문은 `1. 서비스 소개`, `3. 사진 분석`, `6. 처리결과 기록` 화면에 표시되며,
  `6. 처리결과 기록` 화면에서 건별 삭제할 수 있다.

## 10. 데이터 및 모델 한계

| 항목 | 한계 |
|---|---|
| 과거 파손 이력 | **과거 수집 이력**이며 현재 도로 상태가 아니다. 수집되지 않은 파손은 데이터에 없다. |
| 좌표 검증 | 안양시 bounding box(위도 37.34~37.46, 경도 126.87~127.00)로 1차 검증한다. 행정경계 폴리곤이 아니라 사각형이므로 인접 시 경계부가 포함될 수 있다. |
| 도로구간 중요도 | **도로등급·교통량 데이터가 없어**, 해당 노드링크(또는 도로명)에 누적된 과거 이력 건수를 대리지표로 쓴다. 교통량이 많지만 이력이 적은 구간은 과소평가된다. |
| 어린이보호구역 인접도 | 직선거리 기준이다. 실제 통학로/도로 연결성을 반영하지 않는다. |
| 강수 영향 | 단기예보의 가장 이른 예보시각 값 하나를 쓴다. 누적 강수나 동결융해는 반영하지 않는다. |
| 순찰 경로 | **도로망 API 미연동 시 직선(Haversine) 거리 기반 근사 경로**이다. 실제 주행거리·일방통행·회전제한을 반영하지 않으며, 화면에 그 사실을 표시한다. |
| 탐지 모델 | RDD2022 는 해외 도로 위주이다. 안양시 도로 환경(포장 상태, 차선 도색, 촬영 각도)과 차이가 있어 성능이 달라질 수 있다. 국내 데이터로 추가 학습(fine-tuning)이 필요하다. |
| 클래스 | D00/D10/D20/D40 4종만 탐지한다. 맨홀 단차, 소성변형, 포장 침하 등은 탐지하지 않는다. |
| 파손영역 비율 | 세그멘테이션이 아니라 **바운딩 박스 합집합 면적** 비율이다. 실제 파손 면적보다 크게 나온다. |
| 점수 스케일 | 밀도 100점 기준 건수, 보호구역 0점 거리 등은 **화면에서 조정 가능한 가정값**이며 현장 검증을 거치지 않았다. |

## 11. 시험 결과를 기록하는 방법

**이 저장소에는 모델 성능 수치를 미리 적어 두지 않았다.**
아직 학습을 실행하지 않았으므로 적을 실측값이 없기 때문이다.

학습 후 아래 순서로 기록한다.

1. Colab 노트북 `15. 실측 결과 JSON / CSV 내보내기` 셀이
   `outputs/<RUN_NAME>_metrics.json` 과 `.csv` 를 만든다.
2. 두 파일을 로컬 `outputs/` 에 내려받는다.
3. JSON 의 값을 **그대로** 아래 표에 옮겨 적는다. 반올림 외의 가공을 하지 않는다.

```markdown
### 시험 결과 (실행일: YYYY-MM-DD)

- RUN_MODE:            (smoke_test / prototype_train / full_train)
- 사용 국가:            (예: Japan, India, Czech)
- 제외 국가:            United_States (Google Street View 이용조건)
- 분할 방식:            (country_holdout / random_image)
- 학습 이미지 수:       train / val / test
- 모델:                 (yolov8n.pt 등), epochs, imgsz, batch

| 구분 | Precision | Recall | mAP@0.5 | mAP@0.5:0.95 |
|---|---|---|---|---|
| 전체(val)  |  |  |  |  |
| 전체(test) |  |  |  |  |
| D00 종방향 균열 |  |  |  |  |
| D10 횡방향 균열 |  |  |  |  |
| D20 거북등 균열 |  |  |  |  |
| D40 포트홀 |  |  |  |  |

- confusion matrix: `outputs/<RUN_NAME>_confusion_matrix_val.csv`
- 시험 이미지 추론 결과: `outputs/<RUN_NAME>_test_predictions/`
```

> `smoke_test` 로 얻은 수치는 **파이프라인 동작 확인용**이며 성능 근거로 제시할 수 없다.
> 발표자료에 쓸 수치는 최소 `prototype_train` 이상에서 얻는다.

### 실제 실행 기록 1 — smoke_test (파이프라인 검증, 2026-09-08)

**이 수치는 성능 근거가 아니다.** 3 epochs · 학습 이미지 64장으로 파이프라인이
끝까지 도는지만 확인한 것이다. 원본 파일: `outputs/rdd2022_smoke_test_metrics.json`

- 환경: Colab T4 / Python 3.13.15 / ultralytics 8.4.143 / torch 2.11.0+cu128
- 데이터: figshare 원본에서 국가별 400장 부분 내려받기
- 사용 국가: China_MotorBike, Czech, India · **제외: United_States**
- 분할 방식: `country_holdout` (train=China_MotorBike 64장 / val=India 39장 / test=Czech 28장)
- 모델: yolov8n.pt, epochs 3, imgsz 320, batch 8

| 구분 | Precision | Recall | mAP@0.5 | mAP@0.5:0.95 |
|---|---|---|---|---|
| 전체(val)  | 0.0004 | 0.0391 | 0.0014 | 0.0003 |
| 전체(test) | 0.0000 | 0.0000 | 0.0000 | 0.0000 |

확인된 사항: VOC→YOLO 변환, 출처 기준 분할, 학습, 검증, ONNX 변환(입력 `[1,3,320,320]`,
출력 `[1,8,2100]`, 클래스 메타데이터 `D00/D10/D20/D40`), onnxruntime 로딩까지 오류 없이 동작.

### 실제 실행 기록 2 — prototype_train (2026-09-08)

원본 파일: `outputs/rdd2022_prototype_train_metrics.json`

- 환경: Colab T4 / Python 3.13.15 / ultralytics 8.4.143 / torch 2.11.0+cu128
- 데이터: figshare 원본에서 국가별 최대 2,000장 부분 내려받기
- 사용 국가: China_MotorBike, Czech, India, Japan · **제외: United_States**
- 분할 방식: `country_holdout` — 학습 2,754장 / 검증 743장 / 시험 561장
- 모델: yolov8n.pt, epochs 30, imgsz 640, batch 16, seed 42

| 구분 | Precision | Recall | mAP@0.5 | mAP@0.5:0.95 |
|---|---|---|---|---|
| **전체(val)** | 0.1369 | 0.1114 | 0.0725 | 0.0271 |
| D00 종방향 균열 | 0.1203 | 0.1211 | 0.0426 | 0.0143 |
| D10 횡방향 균열 | 0.0265 | 0.0952 | 0.0971 | 0.0379 |
| D20 거북등 균열 | 0.1703 | 0.1381 | 0.0898 | 0.0328 |
| D40 포트홀 | 0.2304 | 0.0912 | 0.0606 | 0.0234 |
| **전체(test)** | 0.2189 | 0.2365 | 0.1253 | 0.0382 |
| D00 종방향 균열 | 0.4178 | 0.2127 | 0.2116 | 0.0754 |
| D10 횡방향 균열 | 0.2011 | 0.2251 | 0.1234 | 0.0315 |
| D20 거북등 균열 | 0.1217 | 0.4141 | 0.1123 | 0.0339 |
| D40 포트홀 | 0.1349 | 0.0940 | 0.0539 | 0.0121 |

**이 수치를 읽을 때 주의할 점**

- **국가 단위로 완전히 분리해 평가한 값이다.** 학습에 쓰지 않은 나라의 도로 사진으로
  검증·시험했으므로, 같은 나라 안에서 이미지를 섞어 나눈 흔한 보고값보다 훨씬 낮게 나온다.
  대신 "처음 보는 환경에서 얼마나 버티는가"를 보수적으로 보여준다.
  안양시 도로에 적용할 때 기대할 수 있는 성능에 더 가까운 쪽은 이 값이다.
- 검증(val) 세트의 D10(횡방향 균열) 객체가 21개뿐이라 해당 클래스 지표는 신뢰구간이 매우 넓다.
  val 과 test 의 순위가 뒤집히는 것도 이 때문이다.
- 클래스별 학습 데이터가 불균형하다(D00 2,491 · D10 1,833 · D20 1,537 · D40 687).
  포트홀(D40)이 가장 적고, 실제로 test 에서 가장 낮은 mAP 를 보인다.
- **국가별 앞부분 2,000장만 사용**했으므로 데이터가 편향돼 있다.
  `full_train` 으로 전체 데이터를 쓰면 값이 달라진다.
- 요약하면, 이 모델은 **시제품 시연용**이며 현장 판단 근거로 쓸 수준이 아니다.
  국내 도로 데이터로 추가 학습(fine-tuning)이 필요하다.

**실제 사진으로 확인한 동작 (2026-09-08)**

학습에 쓰지 않은 RDD2022 Czech 이미지 8장으로 확인했다.

| 신뢰도 임계값 | 8장에서 탐지된 건수 |
|---|---|
| 0.25 (기본값) | 1건 |
| 0.15 | 10건 |
| 0.10 | 14건 |

`outputs/example_detection.jpg` 는 그중 한 장의 결과인데, **관찰된 문제를 그대로 보여준다.**
가장 높은 신뢰도(0.29)를 받은 영역이 도로가 아니라 **하늘과 앞유리 반사** 부분이고,
실제 도로 균열은 0.19 로 더 낮게 잡혔다. 즉 이 모델은 신뢰도 순으로 줄을 세우면
엉뚱한 영역이 위로 올라올 수 있다. 위 mAP 수치가 낮은 이유가 화면에서 이렇게 나타난다.

따라서 시연할 때는 **신뢰도 값을 그대로 보여주고, 담당자 확인 결과로 걸러내는 흐름**을
설명해야 한다. AI 결과만으로 우선순위를 확정하지 않는 이 서비스의 설계 근거이기도 하다.
